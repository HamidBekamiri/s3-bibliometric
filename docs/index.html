S3 step by step

Analyse your literature with S3, step by step

S3 maps the themes of a research field from the titles and abstracts of its papers, checks which map fits your data best, and writes a report organised for a literature review. Use it from Claude, ChatGPT or a Google Colab notebook, without writing code yourself.

Free and open source Runs on your computer, or in Google Colab First run downloads a 420 MB language model (a few minutes) Version 0.14.0
1

Export your papers from Scopus

Select all results → Export → CSV, and tick every information group.

Title (required)Abstract (required) YearCited byAuthorsAffiliations KeywordsReferencesEIDFunding

Each extra field unlocks more of the analysis: references give citation flows and the map comparison, authors and affiliations give the who's who. Web of Science and OpenAlex exports also work.

Give S3 the file exactly as Scopus exported it. Opening and re-saving it in Excel cuts long reference lists at 32,767 characters.

2

Install uv, once (not needed in Colab)

uv starts S3 and installs everything it needs. Paste one line, then close and reopen the window.

Mac: Terminal
curl -LsSf https://astral.sh/uv/install.sh | sh
Windows: PowerShell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
3

Optional: complete references with a Scopus API key

With a key from dev.elsevier.com, S3 fetches every paper's full reference list from Scopus using the EID column of your export: exact citations, and bibliographic coupling from Scopus IDs instead of reference text. Without a key, S3 matches titles in the References column.

Command line (Mac)
export SCOPUS_API_KEY="your-key"
Then add --scopus to the report command.
Claude Desktop: in the config, next to "args"
"env": {"SCOPUS_API_KEY": "your-key"}

Reference lists need your institution's Scopus access: run it on campus or the VPN, or ask your library for an institutional token. Never paste a key into a chat.

Chat runs S3

Claude Desktop

Mac or Windows app
  1. Open Settings → Developer → Edit Config.
  2. Paste this and save:
    { "mcpServers": { "s3-bibliometric": { "command": "uvx", "args": ["s3-bibliometric"] } } }
  3. Quit Claude completely and open it again. S3's tools appear in the tools menu of the chat box.
  4. Ask:
    Compare the maps for ~/Downloads/scopus.csv, run S3 on the recommended one, label the themes and build the literature-review report.

Tools missing? Run which uvx (Mac) or where uvx (Windows) and put that full path in "command". Updating: restart Claude; if the new tools don't show, run uv cache clean s3-bibliometric first.

Chat runs S3

Claude Code

Terminal or the Claude desktop app's Code tab
  1. Add S3 with one command:
    claude mcp add s3-bibliometric -- uvx s3-bibliometric
  2. Ask:
    Compare the maps for my Scopus file, then run S3, show me the themes and the papers to read first, and write the methods paragraph.

Claude asks which language model to use (mpnet, from the S3 paper, is the default) and whether you have a Scopus API key. Never paste a key into the chat.

Notebook runs S3

Google Colab (or Jupyter)

Browser, nothing to install
  1. Open colab.research.google.com → New notebook. Optional: Runtime → Change runtime type → T4 GPU makes the embedding faster.
  2. Install S3 (first cell):
    !pip install -q s3-bibliometric
  3. Upload your Scopus CSV (pick the file when asked):
    from google.colab import files csv = list(files.upload())[0]
  4. Compare the maps, run S3 on the recommended one and download the report:
    import s3bib res = s3bib.run_s3(csv, s3bib.S3Config(map_weights="auto")) print(res.answer("Q0")) res.report("s3_report.html") files.download("s3_report.html")
    print(res.answer("Q0")) shows the map comparison and the map used.

Colab runs on Google's servers, so your file is uploaded there. Scopus API key: store it under Secrets (key icon) as SCOPUS_API_KEY, then run import os; from google.colab import userdata, os.environ["SCOPUS_API_KEY"] = userdata.get("SCOPUS_API_KEY") and s3bib.enrich_citations(res) before the report; Google's servers are off campus, so this usually also needs an institutional token. In Jupyter on your computer, skip the upload cell and use the file path.

You run S3, chat explains

Claude.ai or ChatGPT

Browser or phone
  1. Make the report with one command (change the file path):
    uvx --from s3-bibliometric s3bib report ~/Downloads/scopus.csv --map auto -o ~/Desktop/s3_report.html
    --map auto compares the maps first and uses the recommended one. Press Enter for the default model; answer n if you have no Scopus API key.
  2. Open s3_report.html and click the downloads at the top: themes table, methods paragraph, reading list.
  3. Upload the report and files to the chat, and ask:
    Name each theme in 3–5 words and draft the structure of my literature review, with the gaps to discuss.

Browser chats can't start programs on your computer, so they read the report S3 made instead of running S3 themselves.

What you get: a report organised for your literature review

The field at a glanceNumbers, themes, one paper per theme to read first, trends and gaps.
Theme cardsWhat each theme is about, word clouds, foundations, growth, links between themes.
Research agendaKnowledge gaps and emerging themes for your discussion section.
Methods appendixWhich map was used and why (text alone or text plus citations), a methods paragraph to adapt, a glossary and the validation against other methods.
DownloadsReading lists for Zotero, EndNote or Mendeley (RIS, BibTeX), themes table, PRISMA counts.
