Scopus Export for S3

Export your papers from Scopus for S3

S3 reads one CSV file exported from Scopus. Seven steps, about five minutes. Do them once per literature search.

  1. Sign in through your university

    Open scopus.com from your library's database list, or on campus or the VPN, so Scopus knows your institution has access.

  2. Search, then narrow the results

    Search in Article title, Abstract, Keywords. Advanced search uses the same field as TITLE-ABS-KEY:

    TITLE-ABS-KEY ( "absorptive capacity" ) AND PUBYEAR > 1989

    Then refine with the filters on the left: years, document type (e.g. Article, Review), subject area, language. S3 analyses everything you export, so narrow the search here.

  3. Select all results

    ☐ checkbox above the list→Select all

    Choose all results, not only the documents on the current page.

  4. Export as CSV

    Export→CSV

  5. Tick every information group

    Title and abstract are required. Every other field unlocks more of the analysis:

    Group in the export dialogFields S3 readsWhat S3 does with them
    Citation informationDocument title required, Authors, Year, Source title, Cited by, DOI, EID keyYear orders the map in time and shows growth; Cited by separates local from global foundations; EID links citations and fetches complete references with a Scopus API key
    Bibliographical informationAffiliationsCountries and institutions behind each theme
    Abstract & keywordsAbstract required, Author keywordsThe text S3 compares; keywords describe each theme
    Funding detailsFunding detailsFunders behind each theme
    Other informationReferences (include references)Citation flows between themes, bibliographic coupling, and the map comparison (text alone or text plus citations)

    If the dialog has a "select all information" option, use it. Scopus renames menu items from time to time; look for these fields by name.

  6. Click Export and find the file

    The file downloads to your Downloads folder, usually as scopus.csv. Rename it if you like, e.g. absorptive_capacity_scopus.csv.

  7. Keep the file exactly as exported

    Don't open and re-save it in Excel. Excel cuts any cell at 32,767 characters, so long reference lists of review papers lose their end, and it can change the file's encoding. Viewing without saving is fine.

More results than one export allows?

Scopus caps the number of records in one export. Split the search by publication years (e.g. 1990–2009, 2010–2017, 2018–2025), export each part with the same fields, and put the files together in a notebook cell before running S3:

import pandas as pd, s3bib parts = ["scopus_1990_2009.csv", "scopus_2010_2017.csv", "scopus_2018_2025.csv"] df = pd.concat([pd.read_csv(p) for p in parts], ignore_index=True) res = s3bib.run_s3(df, s3bib.S3Config(map_weights="auto"))

S3 removes duplicate records (same EID, same title and abstract, or same DOI and title), so overlapping year ranges do no harm.

Then give the file to S3

  • Claude Desktop or Claude Code: "Compare the maps for ~/Downloads/scopus.csv, then run S3 and build the report."
  • Command line: s3bib report scopus.csv --map auto
  • Google Colab: upload it in the upload cell.
